Narrow sweep (1 run each), 1T / 16T:

| threshold | AVX-512 | forced AVX2 |
|---|---|---|
| 192 | 144.5k / 1.23M | 126.3k / 0.97M |
| 224 | 144.6k / 1.20M | 122.3k / 0.94M |

| 288 | 146.5k / 1.20M | 124.8k / 0.95M |

**Key finding.** With AVX-512 (what runner 73, the Zen 5 Threadripper, executes) ISPC leads C5
by 8% single-threaded and 5% at 16 threads. Forced to AVX2 on the same Zen 5 it *trails* C5 by
7% single-threaded and 18% at 16 threads, while on Zen 3 the same AVX2 code leads C5 by 10%.
Runner 74 is a QEMU VM with AVX-512 hidden on an unknown host: if that host is Zen 4/5, C5
likely beats us there. The AVX2 path needs work on newer cores (C5's scalar/auto-vectorised
code benefits from Zen 5's wider integer core more than our 256-bit SIMD path does).
256 remains the best threshold for both paths.

## Infrastructure notes

- Visual Studio Enterprise subscriptions (offer 0063P) cannot deploy Spot VMs: every Spot
  create fails preflight with SkuNotAvailable "Capacity Restrictions" in every region.
  Spot works through Azure Batch in BatchService mode (verified with a 1-node pool);
  `batchllmwestus2gves` now has a 128 Spot vCPU quota.
- PrimeC/solution_5 must be built with BuildKit (`docker-buildx`). With Docker's legacy builder
  `RUN ./sieve compileall` sees `/.dockerenv`, takes the "run benchmark" branch, compiles
  nothing and still exits 0.
- A Windows checkout (core.autocrlf) has CRLF files; the bench script uploads LF copies.
